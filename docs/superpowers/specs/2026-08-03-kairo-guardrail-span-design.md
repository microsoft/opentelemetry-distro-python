# Kairo Sample Guardrail Span Design

## Goal

Extend `build/getting_started_with_kairo_exporter` with a deterministic input
guardrail that emits an `apply_guardrail` span. The sample must also print the
exact JSON request body produced by the repository's Agent365 exporter so its
envelope, span fields, attributes, events, and status can be validated.

All implementation changes remain isolated to the Kairo sample. Production
distro and exporter code will not change.

## Architecture

### Guardrail service

Add `src/services/guardrail_service.py` to:

- Evaluate a deterministic local input policy before tool or LLM execution.
- Create an `ApplyGuardrailScope` as a child of the active invoke-agent span.
- Populate every supported field in `GuardrailDetails`.
- Record fixed, non-sensitive input and output values.
- Add a fully populated `GuardrailFinding` event.
- Return an explicit allow or deny result to the message handler.

The service will use the guardrail types from
`microsoft.opentelemetry.a365.core`, ensuring the sample exercises the
repository implementation selected by its editable `uv` source.

### Sample-only payload logging exporter

Add `src/utils/payload_logging_exporter.py` with a sample-only subclass of the
repository's `_Agent365Exporter`. It will:

- Reuse the real exporter filtering, identity partitioning, span mapping,
  envelope construction, truncation, and JSON serialization.
- Filter its input to `apply_guardrail` spans so console output is focused.
- Override only the HTTP-send method to print the exact serialized request body
  between clear markers and return success.
- Never replace, intercept, or disable the normally configured Kairo exporter.

`start_server.py` will register this exporter through an additional
`SimpleSpanProcessor` after the normal observability `configure()` call. The
real Kairo exporter will continue sending telemetry independently.

## Data Flow

1. The existing message handler creates and enters the invoke-agent scope.
2. The handler calls the deterministic guardrail service before tools or Azure
   OpenAI.
3. The guardrail service creates an `apply_guardrail` child span and populates
   its complete validation dataset.
4. A benign message records an allow decision and processing continues.
5. A documented trigger phrase records a deny decision, returns a blocked
   response, and prevents tool and LLM execution.
6. When the guardrail span ends, both the real Kairo processor and the
   sample-only logging processor receive it.
7. The logging exporter prints the exact OTLP-like JSON request body generated
   by the real exporter implementation.

The recorded content value will be a fixed non-sensitive sample string rather
than the live user message. Its SHA-256 hash will be computed from that same
fixed value so the example remains internally consistent.

## Exported JSON Contract

The logged body will preserve the exporter contract:

- Root `resourceSpans` array.
- Resource object with `attributes`.
- `scopeSpans` array containing `scope` and `spans`.
- Span fields including trace and span identifiers, parent identifier, name,
  kind, nanosecond timestamps, attributes, events, links, and status.
- A complete `microsoft.security.finding` event.
- All guardrail detail, content, identity, request, user, policy, decision, and
  risk attributes populated by the sample.

Dynamic values such as trace IDs, span IDs, and timestamps will remain genuine
runtime values. Tests will validate their format rather than replace them with
placeholders.

## Error Handling

- Guardrail evaluation failures will propagate to the existing message-handler
  error path and be recorded on the invoke-agent scope.
- A failure will not silently become an allow decision.
- Logging-exporter failures will be reported through the OpenTelemetry exporter
  result and will not alter the real Kairo exporter's behavior.
- Denied content will produce a clear user response without calling tools or
  Azure OpenAI.

## Testing

Add sample-local tests that require no Azure credentials or network access:

- Allow behavior continues processing.
- Deny behavior returns a blocked result.
- The guardrail span contains every configured guardrail attribute.
- The finding event contains every configured event attribute.
- The logging exporter output parses as JSON.
- Exact key sets are asserted at the envelope, resource, scope, span, event,
  and status levels.
- Trace IDs, span IDs, parent IDs, and timestamps have valid exporter formats.
- Every attribute generated by the sample appears in the captured request body
  with its expected value.

The README will document setup, the allow and deny prompts, console markers, and
an example of the complete captured request body.

## Non-Goals

- Calling Azure AI Content Safety or another external guardrail service.
- Changing the production Agent365 exporter or distro behavior.
- Logging live user content.
- Replacing the configured Kairo exporter.
